# 旅行点维护（给人和 agent）

蟹鱼游的旅行点由人或 agent（Claude、Codex、Grok Bot）按这份说明增删改。只改种子，其余由脚本生成。

## 文件

| 文件 | 谁写 | 内容 |
| --- | --- | --- |
| `data/places.inbox.json` | 用户、agent | 线索收件箱：看到的地方和链接（小红书、X、Instagram 帖子也放这里），先不核实 |
| `data/places.seed.json` | 人、agent | 正式种子：一处一行。顶层还有标签词表 `tags` 和不收录名单 `excluded` |
| `scripts/validate_places.py` | — | 检查种子；有错误时退出码为1 |
| `scripts/collect_places.py` | — | 先检查，再补坐标、配图署名、自驾时间，生成 `data/places.json` |
| `data/places.json` | 脚本 | 页面读取的数据，不要手改 |
| `scripts/collect_events.py` | — | 从 `events.json` 取出还没结束的活动，补会场坐标（缓存在 `data/venues.json`），生成 `data/events.current.json`，地图的「🎟️ 活动」按钮读它 |
| `data/events.seed.json` | 人、agent | 蟹鱼游自己收集的活动（灯饰、点灯、市集、展览等），每条带来源；`collect_events.py` 把它和 events.json 里未结束的合并 |
| `data/greenapple.json` | 人、agent | 绿苹果专区：Mrs. GREEN APPLE 在关西的地点和活动，检查脚本一起校验 |

## 收什么、不收什么

- **收**：恒定、长期存在、值得专门出门去的地方（山、寺社、古街、庭园、海岸、温泉乡、有特色的美术馆和建筑）。以大阪京桥站为中心，公共交通或自驾单程3小时以内。
- **不收**：
  - 临时活动和展览（它们是活动，不是旅行点）；
  - 大阪、京都市内过于知名的地标（道顿堀、通天阁、八坂神社、清水寺、金阁寺等，见 `excluded`）；
  - 商场、连锁店、一般餐厅；
  - 没有可靠来源确认仍在营业或开放的地方。
- 用户明确说过不要的，加进 `excluded` 并写原因，以后不再加回。

## 添加一处的步骤

1. **找线索**：从收件箱取一条，或按主题搜索（例如“大阪 近郊 紅葉 穴場”“京都 紫陽花 寺”）。社交平台的帖子只当线索，不引用、不复制图片和文字。
2. **核实**（至少两个来源，其中尽量有一个是官方或观光协会）：
   - 名称、是否仍开放、开放时间和季节；
   - 从京桥出发的公共交通路线和单程分钟数（含换乘和步行）。用换乘工具查工作日上午出发的结果，写在 `transit.route` 里；
   - 季节窗口用往年常见的时段，写成 `MM-DD`。每年变动大的（红叶、樱花）宁可略宽。
3. **写进种子**，在 `places` 末尾加一行。必填字段：

   | 字段 | 说明 |
   | --- | --- |
   | `id` | 小写英文和连字符，一次分配，以后改名也不变 |
   | `name` | 中文名，可以带“·”加副名 |
   | `wiki` | 日文维基百科条目名，用来取坐标和配图；没有条目就写 `ll: [经度, 纬度]` |
   | `area` | 大阪、京都、奈良、兵库、滋贺、和歌山、三重、鸟取 |
   | `kind` | 寺社、自然、历史、街区、公园、温泉、展望、美术馆等 |
   | `transit` | `{ "mins": 整数, "route": "怎么去" }` |
   | `seasons` | `[{ "from": "MM-DD", "to": "MM-DD", "label": "红叶", "tone": "koyo" }]`；色调：koyo 红叶系、sakura 樱粉、ume 紫、green 绿、onsen 温泉紫、plain 灰；全年可去就留空 `[]` |
   | `why` | 一句话：为什么值得去 |
   | `tip` | 一句实用提示，没有就留空字符串 |
   | `tags` | 从顶层 `tags` 词表里选；「最近热门」由季节自动判断，不要写 |
   | `blurb` | 画册里的景观描写，25–90字，用自己的话写画面和感受，不写交通时间，不照抄来源 |
   | `sources` | `[{ "url": "...", "note": "确认了什么" }]`，至少一个 |
   | `addedAt`、`addedBy` | 收录日期（YYYY-MM-DD）和执行者 |

4. **检查并生成**：
   ```sh
   python3 scripts/validate_places.py
   python3 scripts/collect_places.py
   ```
   生成脚本会报告缺坐标或缺配图的条目；缺坐标就在种子里补 `ll`。
5. **预览**：本机打开 `lab/spots/`（正式版上线后改为正式页面），在时间圈、地图和画册里各看一眼新地点。
6. **收尾**：收件箱里对应的线索改成 `已收录`（写 `placeId`）或 `不收`（写原因）。提交时首行写 `[FROM:<执行者>]`，说明加了哪几处。本仓库 main 就是公开发布源，推送等于发布，先按 PROJECT 的发布流程协调。

## 绿苹果专区

用户要求着重留意 Mrs. GREEN APPLE（绿苹果乐队）在关西的相关地点和活动。

- **活动**：演唱会、快闪店、主题咖啡店、公开录音、合作展览等，只收关西（含神户）的场次。写 `from`/`to`（未公布写 `null` 并写 `dateNote`）、会场、经纬度（地点未公开写 `null`）、要知道的事（预约、抽选、购票方式），至少一个来源。结束的活动页面自动隐藏，过一阵可以从文件里删掉。
- **地点**：MV取景地、成员公开提到的店和地方等，必须有官方或可靠媒体来源；只有粉丝帖或问答时不收，在 `placesNote` 里记一笔。
- **查哪里**：官网 mrsgreenapple.com 的新闻、粉丝俱乐部 Ringo Jam 公告、音乐媒体（音楽ナタリー、Real Sound、ORICON）、合作方公告（丸井、BOX cafe&space、FM802）。
- 每次查完更新顶层 `checkedAt`。建议每周查一次；固定检查可以交给一个 Bot 或定时任务，按下面的任务写法执行。

> 读 `projects/kansai-events/docs/旅行点维护.md` 的“绿苹果专区”，搜索 Mrs. GREEN APPLE 最近在关西（大阪、京都、兵库、奈良、滋贺、和歌山）的活动和相关地点，核实后更新 `data/greenapple.json`，运行 `scripts/validate_places.py`，结果写在任务文件里。不要推送。

## 标签（也由人或 agent 维护）

标签定义在种子顶层 `tags`，每个是 `{ "name", "emoji", "desc"?, "rule"? }`。页面按数量从多到少排列，选中多个时取“或”。

- **普通标签**（没有 `rule`）：写进各地点的 `tags`。新增一个就是在词表加一项，再给相关地点加上。
- **季节标签** `rule: { "type": "season", "labels": ["红叶"], "withinDays": 21 }`：地点的季节窗口里有这些 label，且正当时或在 N 天内开始，就自动算进来。例：🍂 秋叶季。春天可以照样加一个“🌸 樱花季”。
- **名单标签** `rule: { "type": "list", "ids": [...], "checkedAt": "YYYY-MM-DD", "sources": [...] }`：由 agent 按来源维护名单。例：🤳 最近网红——搜索最近被媒体和社交平台讨论多的关西地方，名单里只放已收录的地点（没收录的先按上面的步骤收录），每次更新改 `checkedAt` 和来源。
- **专区** `rule: { "type": "zone" }`：🍏 绿苹果，数据在单独的文件。
- 检查脚本会拦下：规则标签被写进地点的 `tags`、名单里有不存在的地点、名单缺来源。

## 一轮信息搜集怎么做

1. 地点：按“大阪出发 日归 穴场/绝景”“滋贺/奈良/兵库/和歌山 日归”“好吃/好玩”等主题搜索；旅行网站、电子杂志、维基百科都可以当来源。小红书、X、Instagram、微博、B站需要登录，网页搜索只能看到被索引的部分，只当线索，再到官网、观光协会或媒体核实。
2. 活动：搜索当季的灯饰、红叶点灯、圣诞市集、展览、合作活动，核实起止日期和会场后写进 `data/events.seed.json`。
3. 还没核实或日期未公布的，放进 `data/places.inbox.json`，`status` 留空，下一轮再看。
4. 运行检查、`collect_places.py` 和 `collect_events.py`，在页面里看一眼。

## 修改与删除

- 改名、改季节、改路线：直接改那一行，`id` 不变。
- 关闭或不再推荐：把这一行移出 `places`，在 `excluded` 里记 `id`、`name`、原因和日期。
- 公共交通时间核实过的，可在 `transit` 里加 `"checked": "YYYY-MM-DD"`（脚本会保留）。

## 给 agent 的任务写法

> 读 `projects/kansai-events/docs/旅行点维护.md`，从 `data/places.inbox.json` 里处理状态为空的线索；另外按“<主题>”找3处京桥3小时内、还没收录的旅行点。按说明核实、写入种子、运行检查和生成，结果写在任务文件里。不要推送。
