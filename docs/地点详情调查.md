# 地点详情调查（给人和执行调查的模型）

蟹鱼游每处旅行点在 `data/places.json` 里只有一句 `why`、一句 `tip` 和一段 `blurb`。详细攻略另放一份文件，由用户指定的模型做网页调查后写入，页面打开详情时再读取。没有详情文件的地点照常显示，只是少了“详细攻略”那一段。

## 文件

| 文件 | 谁写 | 内容 |
| --- | --- | --- |
| `docs/prompts/地点详情调查.prompt.md` | 人 | 给调查模型的提示词模板，`{{...}}` 由脚本填入 |
| `scripts/detail_prompt.py` | — | 按地点 id 生成填好的提示词；`--missing` 列出还没有详情的地点 |
| `data/details/<id>.json` | 调查模型（经人或 agent 放入） | 一处一个文件，格式见下 |
| `scripts/collect_details.py` | — | 检查所有详情文件，生成 `data/details/index.json`；有错误时退出码为1 |
| `data/details/index.json` | 脚本 | 页面读取的清单（哪些地点有详情、核实日期、revision），不要手改 |
| `lab/details-sample/` | Claude | 本机预览用的合成样例，内容是编的，不能发布进 `data/details/` |

## 流程

1. 选地点：`python3 scripts/detail_prompt.py --missing` 看哪些还没做；
2. 生成提示词：`python3 scripts/detail_prompt.py osakajo minoo > /tmp/prompt.md`（一次可以多个 id，每个 id 一段）；
3. 交给能上网搜索的模型执行，要求它只输出 JSON；
4. 把每处的 JSON 存成 `data/details/<id>.json`；
5. `python3 scripts/collect_details.py` 检查并生成清单；报错就退回给模型修正，或手工改；
6. 本机预览打开该地点详情看一眼，再按 PROJECT 的发布流程发布。

重新调查同一处时，`revision` 加1，`checkedAt` 改成新日期，整份替换。

## 数据格式（schema 1）

只有 `id`、`schema`、`revision`、`checkedAt`、`researchedBy`、`summary`、`sources` 必填；其余字段查不到就省略或写 `null`，不要猜。所有文字用简体中文，日文专名保留原文（可在括号里加中文）。

```json
{
  "id": "osakajo",                 // 必须是 places.json 里已有的 id
  "schema": 1,
  "revision": 1,                   // 每次重新调查加1
  "checkedAt": "2026-11-02",       // 调查日期 YYYY-MM-DD
  "researchedBy": "模型名",
  "summary": "两到四句：这是什么地方、适合谁、最值得看的是什么。",
  "highlights": [                  // 看点，3–6条
    { "title": "西之丸庭园", "text": "一两句说明看什么、为什么值得。", "where": "公园西侧，需另购票" }
  ],
  "visit": {                       // 实用信息，每项一句
    "hours": "开放时间与休息日",
    "fee": "门票或主要收费",
    "stay": "建议停留多久",
    "bestTime": "一天里什么时候去最好、为什么",
    "crowd": "人多不多，什么时候人少"
  },
  "access": {
    "transit": "从京桥站出发的具体路线：线路、换乘站、下车站、出口、步行分钟",
    "car": "自驾与停车：停车场名称、大致费用、旺季是否难停",
    "local": "到了之后怎么逛：步行路线、园内交通、上坡多不多"
  },
  "food": [                        // 附近吃什么，0–5条；只写确认仍在营业的
    { "name": "店名（原文）", "what": "招牌是什么", "price": "人均大致价格", "note": "排队、预约、营业时间等" }
  ],
  "nearby": [                      // 顺路还能去，0–5条
    { "name": "名称", "placeId": "如果是本站已有地点，写它的 id，否则省略", "how": "步行10分钟 / 电车2站", "note": "一句为什么顺路" }
  ],
  "seasonal": [                    // 各季节分别看什么，0–4条
    { "when": "3月下旬–4月上旬", "text": "樱花，西之丸庭园有夜樱。" }
  ],
  "tips": ["实用提示，每条一句，0–6条"],
  "cautions": ["注意事项：施工、闭馆、禁止事项、安全等，0–4条"],
  "search": {                      // 去外部网站搜索时用的关键词，可省略
    "zh": "小红书上常用的中文叫法",
    "ja": "日文正式名称或常用叫法"
  },
  "links": [                       // 官网、观光协会等，0–4条
    { "label": "官方网站", "url": "https://..." }
  ],
  "images": [                      // 多图，3–8张，只用 Wikimedia Commons 的自由许可图片；第一张最有代表性
    { "file": "Osaka_Castle_02bs3200.jpg", "caption": "从西之丸庭园看天守" }
  ],
  "sources": [                     // 至少2条，每条写确认了什么
    { "url": "https://...", "note": "开放时间、门票", "accessed": "2026-11-02" }
  ]
}
```

（上面的 `//` 只是说明，实际文件是标准 JSON，不能带注释。）

### 检查规则（`collect_details.py`）

- 文件名与 `id` 一致，`id` 存在于 `data/places.json`；`schema` 为 1，`revision` 为正整数，`checkedAt` 为 YYYY-MM-DD；
- `summary` 20–200字；`highlights` 不超过6条，每条要有 `title` 和 `text`；
- `sources` 至少2条，`url` 以 http 开头；`links` 的 `url` 以 http 开头；
- `nearby[].placeId` 如果写了，必须是已有地点；
- `images[].file` 只写 Commons 文件名，不带网址；不带 `--check` 运行时脚本联网向 Commons 查缩略图、作者和许可，找不到或许可不是 CC0、CC BY、CC BY-SA、公有领域的报错。查到的写进 `index.json` 的 `images`；`places.json` 里原来的那张代表图仍保留；
- 只允许上面列出的字段，多出来的字段报错（防止模型自造结构）；
- 带 `"sample": true` 的文件不能放进 `data/details/`。

## 多图

- 生成提示词时，`detail_prompt.py` 会向 Commons 查坐标在地点1.5公里以内的图片作为候选列给模型，模型从中挑或另找，只写文件名。
- 页面里：详情顶部的照片可以左右滑，看全部图片，每张的作者和许可显示在下方；画册瀑布流第二轮起换用其他图片，同一处每轮看到的照片不同。
- 只用 Commons，是因为许可明确、可以直接引用缩略图；小红书、Instagram 等的图片有版权，不能放进站里。

## 内容规则

- 每条事实都要能在 `sources` 里找到出处；营业时间、门票等易变信息写明是调查当天的情况。
- 社交平台（小红书、X、Instagram）只当线索，不引用原文、不复制图片；可以据此再去官方或媒体核实。
- 用自己的话写，不整段照抄来源。
- 不写价格以外的商业推广，不写“必去”“绝美”之类的夸张词。
